# ZY_WEB 安裝、啟動、部署與帳號操作手冊

更新日期：2026-11-10（Asia/Taipei）  
適用：目前 Vue 3＋PWA／Django API／MySQL 8.4 版本；供接手部署與資訊公司管理者使用。

搭配閱讀：[技術架構與檔案用途說明](技術架構與檔案用途說明.md)。本文件不包含任何現有密碼、私鑰或驗證連結。

## 1. 先選擇交付方式

| 情境 | 路線 | 帳號及資料處理 |
|---|---|---|
| 在目前這台 Windows 電腦繼續使用 | 第3節日常啟動 | 保留現有資料，已有管理者，不重新初始化 |
| 交給別人在新電腦試用，使用全新空資料庫 | 第4節全新 Windows 安裝 | 新建 .env、資料庫、第一位管理者 |
| 多家公司從網路正式使用 | 第5節 Linux／Docker／HTTPS | 使用正式網域、TLS、專用憑證、備份與程序自動重啟 |
| 搬移既有資料 | 第10節資料移轉 | SQL匯出／匯入＋附件，沿用資料內的帳號，不重新bootstrap |

**目前已驗證的是 Windows 本機與 MySQL／Edge 測試；Docker正式部署尚未在本機實際執行驗收。** 下面的正式部署步驟依現有設定檔整理，接手者仍須在目標主機完成驗收。

## 2. 交付哪些檔案

應交付前後端程式碼、frontend/package-lock.json、migrations、必要靜態檔、requirements、scripts、deployment、.env.example及說明文件。不交付node_modules；frontend/dist由Node或Docker重新建置。根目錄名稱維持 ZY_WEB。

全新部署不要直接複製下列本機資料：

| 項目 | 原因與處理 |
|---|---|
| `.env` | 含資料庫及Gmail機密；新主機從範例另建 |
| `.mysql-admin.env` | 目前本機便攜MySQL的管理憑證；不是通用部署密碼 |
| `.venv/` | 綁定本機環境，需重新安裝 |
| `mysql_data/` | 活的資料庫檔案，不能直接當程式安裝包搬動 |
| `private_media/`、`backups/` | 含業務附件及資料；只有移轉需求時受控交付 |
| `.mysql.pid`、`.web.pid`、`.worker.pid` | PID只屬於來源電腦，不能在新主機沿用 |
| `.tools/` | 本機Windows MySQL便攜執行檔；Docker／既有MySQL不需要 |
| `__pycache__/`、`.ruff_cache/` | 可重建的快取 |

本版只增加Vue/API改版必要測試，沒有恢復舊的測試備份或大量產物。新主機不存在固定通用的 zyadmin 密碼，不使用先前聊天中的臨時密碼。

## 3. 目前 Windows 電腦的日常啟動

開啟 PowerShell，切到實際專案根目錄，例如：

```powershell
Set-Location 'C:\Users\user\Desktop\ZY_WEB'
powershell -ExecutionPolicy Bypass -File scripts/start_mysql.ps1
# 首次或前端更新後建置，已建置且程式未變更時可省略
powershell -ExecutionPolicy Bypass -File scripts/build_frontend.ps1
.\.venv\Scripts\python.exe scripts/check_environment.py
.\.venv\Scripts\python.exe backend/manage.py check
```

目前專用資料庫是 **127.0.0.1:3307、zy_web、MySQL 8.4**。3306是原有的其他服務；即使也有zy_web資料庫，內容不相同。可用資料庫工具執行唯讀確認：

```sql
SELECT @@port, VERSION(), DATABASE();
SHOW TABLES FROM zy_web;
```

開兩個終端機，分別啟動：

```powershell
# 終端機 A：網站
.\.venv\Scripts\python.exe backend/manage.py runserver 127.0.0.1:8000
```

```powershell
# 終端機 B：寄信worker
.\.venv\Scripts\python.exe backend/manage.py process_notifications --loop
```

本機瀏覽 http://127.0.0.1:8000/ 。前景程序可用 Ctrl+C 停止。這兩個程序缺一個，就可能出現「網站可以操作，但Email一直排隊」。

若本機預覽站已由先前維運程序在背景啟動，請勿再佔用同一個8000埠或重複啟動worker；先確認該專案的程序，再由維運人員停止／重新啟動。PID檔是識別提示，不是開機自動啟動服務。

**修改.env後必須重新啟動網站及worker；runserver不保證因.env變更而重新載入。** 目前啟動腳本不會自動把worker一併開啟。一般重啟不需要再跑setup_mysql.py或bootstrap_admin。

## 4. 全新 Windows 安裝（測試／試用）

### 4.1 安裝與準備

1. 安裝Python 3.11、Node.js 24 LTS、Oracle MySQL 8.4及可選的MySQL Workbench。不要假設叫MySQL的既有服務就一定是相容版本。
2. 將程式碼放到自己的ZY_WEB資料夾，以下命令都在專案根目錄執行。
3. 確認MySQL版本、連接埠及應用專用帳號。

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

將最後產生的字串填入.env的SECRET_KEY。不要覆蓋已有正式設定的.env。本精簡交付版只保留應用執行依賴。Gunicorn套件用於Linux正式服務，不在Windows上啟動Gunicorn。

### 4.2 選一種資料庫方式

**方式A：使用接手主機已安裝的MySQL（較通用）**

由資料庫管理者登入MySQL後，在全新安裝情境執行以下範例。將`CHANGE_ME_APP_PASSWORD`改成新產生的密碼，不使用來源電腦密碼；已有同名帳號／資料庫時先確認，不能任意重建。

```sql
CREATE DATABASE zy_web CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'zy_web'@'localhost' IDENTIFIED BY 'CHANGE_ME_APP_PASSWORD';
GRANT ALL PRIVILEGES ON zy_web.* TO 'zy_web'@'localhost';
-- 僅測試環境需要：可建立與清理專用測試庫，不授予其他業務庫權限。
GRANT ALL PRIVILEGES ON test_zy_web.* TO 'zy_web'@'localhost';
```

.env的MYSQL_PORT填實際MySQL埠，可能是3306，也可能是3307；MYSQL_USER填應用專用帳號。若MySQL在遠端，帳號允許的來源主機也要由DBA依實際網路調整，不直接開放所有來源。

**方式B：建立本專案的Windows便攜MySQL（僅開發／試用）**

下載官方MySQL 8.4.13 Windows ZIP，解壓後讓以下路徑存在：

```text
ZY_WEB/.tools/mysql-8.4.13-winx64/bin/mysqld.exe
```

確認.env已建立、3307未使用、根目錄沒有mysql_data後執行：

```powershell
.\.venv\Scripts\python.exe scripts/setup_mysql.py
```

它會建立mysql_data、專用zy_web資料庫、應用及本機管理密碼，將應用密碼寫回.env，管理憑證存於.mysql-admin.env。**只適用全新初始化；資料目錄存在會拒絕重建，不能刪掉資料夾來解決一般啟動錯誤。** 不使用點號開頭的資料目錄。本機後續啟動使用start_mysql.ps1。

### 4.3 本機.env範例

下列都是範例，不含可直接使用的真實密碼；資料庫埠依4.2所選方式填寫。

```dotenv
ZY_DEBUG=1
SECRET_KEY=REPLACE_WITH_YOUR_RANDOM_SECRET
ALLOWED_HOSTS=localhost,127.0.0.1
SITE_URL=http://127.0.0.1:8000
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3307
MYSQL_DATABASE=zy_web
MYSQL_USER=zy_web
MYSQL_PASSWORD=REPLACE_WITH_YOUR_DATABASE_PASSWORD
MYSQL_TEST_DATABASE=test_zy_web
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_HOST_USER=your-service-account@gmail.com
EMAIL_HOST_PASSWORD=REPLACE_WITH_GOOGLE_APP_PASSWORD
EMAIL_USE_TLS=1
DEFAULT_FROM_EMAIL=${EMAIL_HOST_USER}
SECURE_SSL_REDIRECT=0
SESSION_COOKIE_SECURE=0
CSRF_COOKIE_SECURE=0
PDF_FONT_PATH=
```

.env.example預設仍是console寄信模式；照抄範例後必須自行改成SMTP並填帳密。環境變數優先於dotenv檔案，若主機或容器已定義同名變數，單改檔案可能不生效。開關用1／0，不用True／False。

Windows PDF預設找系統微軟正黑體；若沒有，安裝可用中文字型並設定PDF_FONT_PATH到實際TrueType／TTC檔案。

### 4.4 建置Vue、建立表、第一位管理者與啟動

先在根目錄執行（新主機不沿用來源電腦node_modules）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_frontend.ps1 -Install
```

這會使用鎖檔安裝並執行型別檢查／Vite建置。frontend/dist存在後，manage.py runserver就會提供新Vue畫面，不需開另一個Vite服務。

```powershell
.\.venv\Scripts\python.exe scripts/check_environment.py
.\.venv\Scripts\python.exe backend/manage.py check
.\.venv\Scripts\python.exe backend/manage.py migrate --noinput
.\.venv\Scripts\python.exe backend/manage.py bootstrap_admin --username zyadmin
```

`migrate`會依交付的migrations建表，不需要手動建立每一張表；一般部署不要自行執行makemigrations改變資料結構。全新空庫的check_environment可能尚未列出業務表，migrate後再確認。

bootstrap_admin會顯示新管理者的臨時密碼，僅當次顯示、24小時有效；自行交付給管理者，不存入交接MD。首次登入要輸入目前臨時密碼及新的個人密碼，至少10字元、不能沿用目前密碼，亦有常見／純數字／相似度限制。

接著依第3節啟動網站及worker。**不要使用Django原生createsuperuser代替bootstrap_admin**；本系統依業務角色及公司限制管理帳號，且未提供Django admin後台入口。

## 5. Linux／Docker正式部署

### 5.1 目前設定與上線前準備

架構：Nginx提供Vue/PWA靜態檔；/api/、附件及報表轉送Gunicorn/Django（容器內8000）→ MySQL；獨立worker處理Email。Dockerfile先用Node建置Vue，再產出web與proxy兩個target，Compose會選擇正確target。

準備Linux主機、Docker Engine與Compose外掛、正式網域、DNS、TLS憑證、SMTP帳號與備份空間。本段依現有compose.yaml整理，**尚未在目標主機執行驗證**。本compose預設建立自己的db服務；如要沿用外部MySQL，必須先調整web／worker的MYSQL_HOST及depends_on，不能只修改.env，因為compose的environment會覆蓋部分設定。

### 5.2 正式.env

新建正式.env，不能沿用來源電腦的SECRET_KEY、資料庫或Gmail密碼。以第4.3範例為基礎，至少調整：

```dotenv
ZY_DEBUG=0
SECRET_KEY=REPLACE_WITH_PRODUCTION_RANDOM_SECRET
ALLOWED_HOSTS=repair.example.com
SITE_URL=https://repair.example.com
MYSQL_HOST=db
MYSQL_PORT=3306
MYSQL_DATABASE=zy_web
MYSQL_USER=zy_web
MYSQL_PASSWORD=REPLACE_WITH_PRODUCTION_APP_DATABASE_PASSWORD
MYSQL_ROOT_PASSWORD=REPLACE_WITH_DIFFERENT_DATABASE_ROOT_PASSWORD
MYSQL_TEST_DATABASE=test_zy_web
SECURE_SSL_REDIRECT=1
SESSION_COOKIE_SECURE=1
CSRF_COOKIE_SECURE=1
```

另填入第7節SMTP設定。ALLOWED_HOSTS只填主機名稱，不含https://或路徑；多個主機以逗號分隔。SITE_URL必須是使用者能開啟的正式網址，**不能填127.0.0.1**，否則客戶在其他電腦收到的驗證連結會指向他自己的電腦。

目前compose的db名稱與帳號固定為zy_web，請與上例一致。MYSQL_ROOT_PASSWORD是compose初始化MySQL需要的參數，不是應用登入密碼，也不在目前.env.example內，正式部署須自行新增。使用不同的應用與root密碼。可用Python secrets.token_urlsafe產生密碼以降低dotenv跳脫問題。

MySQL映像的初始化環境變數只在**空資料卷首次初始化**生效；已有資料後修改.env不會自動修改MySQL內的帳號密碼，需由DBA配合更新，不可為改密碼刪除資料卷。

### 5.3 憑證與服務維護

建立以下檔案，名稱與nginx.conf一致：

```text
ZY_WEB/backend/deployment/certs/fullchain.pem
ZY_WEB/backend/deployment/certs/privkey.pem
```

憑證須適用正式網域，私鑰不進版本控制；準備續期及重載Nginx機制。現有Nginx只開443，未包含80轉址與自動申請憑證流程。若自行配置server_name，使用自己的正式網域。

現有compose已對db、web、worker、proxy設定`restart: unless-stopped`；仍需驗證主機Docker服務自動啟動與程序故障恢復。MySQL與web容器內的8000不應直接暴露到公網，只公開反向代理的443。

Nginx會設定X-Forwarded-Proto，Django僅在正式模式信任該標頭，因此web不能被不可信來源繞過代理直接存取。現在HSTS會涵蓋子網域，啟用前確認同網域政策與HTTPS配置。[Django部署檢查說明](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/)

### 5.4 建置與首次初始化

在ZY_WEB根目錄執行；命令中的--env-file用於compose變數展開，env_file則用於容器環境，兩者用途不同。[Docker官方說明](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/)

```bash
# 只驗證設定，不將解析出的帳密輸出到交接紀錄
 docker compose --env-file .env -f backend/deployment/compose.yaml config --quiet
 docker compose --env-file .env -f backend/deployment/compose.yaml build web worker proxy
 docker compose --env-file .env -f backend/deployment/compose.yaml up -d db
 docker compose --env-file .env -f backend/deployment/compose.yaml ps
```

確認db健康後：

```bash
docker compose --env-file .env -f backend/deployment/compose.yaml run --rm web python manage.py check --deploy
docker compose --env-file .env -f backend/deployment/compose.yaml run --rm web python manage.py migrate --noinput
docker compose --env-file .env -f backend/deployment/compose.yaml run --rm web python manage.py collectstatic --noinput
docker compose --env-file .env -f backend/deployment/compose.yaml run --rm web python manage.py bootstrap_admin --username zyadmin
docker compose --env-file .env -f backend/deployment/compose.yaml up -d web worker proxy
```

保存當次臨時密碼供本人首次登入，打開https://repair.example.com/完成改密碼。check --deploy若有警告須由接手者判讀與修正；不能將命令執行成功視為整個部署已驗收。

```bash
docker compose --env-file .env -f backend/deployment/compose.yaml ps
docker compose --env-file .env -f backend/deployment/compose.yaml logs --tail=100 web worker proxy
```

日誌可能含網址或業務資訊，不將完整日誌直接公開。修改.env後使用`up -d --force-recreate web worker`讓容器重新取得環境；僅restart既有容器不會更新env_file帶入的環境變數。

若正式容器缺少PDF字型、資料卷寫入權限或TLS設定，先修正再驗收；不以本機Windows通過結果替代。現有Dockerfile會安裝Linux文泉驛正黑字型及編譯mysqlclient的系統套件。

## 6. 首次登入與四種角色建立步驟

### 6.1 第一位資訊公司管理者

全新資料庫才執行bootstrap_admin，取得帳號與臨時密碼；使用者登入後先改個人密碼。命令發現已有任何資訊公司管理者（包括停用或刪除紀錄）就拒絕再次bootstrap，以免重複建立。搬資料庫時帳號已在備份內，不再bootstrap。

系統沒有公開註冊入口；所有後續帳號都由資訊公司管理者建立。建議至少建立第二位資訊公司管理者作備援。

### 6.2 先建立客戶公司

1. 用資訊公司管理者登入。
2. 左側「公司管理」→「＋新增公司」。
3. 填公司名稱、唯一公司代碼、聯絡資料、啟用狀態。
4. 辦公室／據點每行一筆；進度通知收件人選填，每行一筆。
5. 儲存後系統建立V1固定報修欄位。
6. 有額外欄位需求時，到「表單版本」選公司、建立草稿、確認再發布。

目前據點欄位是增補清單，移除輸入行不代表自動刪除歷史據點。公司停用會阻擋所屬人員登入；歷史案件保留。

### 6.3 建立資訊公司管理者（後續備援帳號）

1. 現有資訊公司管理者進入「帳號管理」→「＋新增帳號」。
2. 填登入帳號、姓名；角色選「資訊公司管理者」。
3. **所屬公司留空**；Email選填。
4. 儲存後將顯示的臨時密碼交給本人，首次登入強制更換。
5. 此角色能管理所有公司、帳號、派工及操作紀錄，請只授予需要的管理人員。

### 6.4 建立資訊公司工程師

1. 資訊公司管理者進入「帳號管理」→「＋新增帳號」。
2. 角色選「資訊公司工程師」，**所屬公司留空**。
3. 填其他基本資料及選填Email後儲存，交付臨時密碼。
4. 工程師首次登入更換密碼後，首頁可能沒有案件，這是正常情況。
5. 管理者開啟一張案件，在「指派／改派工程師」選該工程師、填原因並確認；工程師才會看到這張案件。

工程師不能自己建立公司或帳號、不能自行搶單；被改派後原工程師失去該案存取權。

### 6.5 建立公司管理者

1. 資訊公司管理者進入「帳號管理」→「＋新增帳號」。
2. 角色選「公司管理者」，**所屬公司必須選剛建立的客戶公司**。
3. 填基本資料、選填Email，儲存並交付臨時密碼。
4. 本人首次登入改密碼，可看本公司全部案件及維護本公司報修者基本資料。
5. 公司管理者不能新增、啟停、刪除帳號，也不能建立其他公司管理者。

### 6.6 建立公司報修者

1. 資訊公司管理者進入「帳號管理」→「＋新增帳號」。
2. 角色選「公司報修者」，**所屬公司必填**。
3. 填姓名、工號、部門、辦公室、電話、手機及選填Email。
4. 儲存後交付臨時密碼；首次登入改密碼後即可報修。
5. 只能看自己的案件；Email未填不影響報修，使用站內通知查進度。

### 6.7 帳號共通規則與權限表

- 帳號3至150字元，小寫英數起頭，其餘允許英數、小數點、底線、減號；系統轉小寫且唯一。
- 登入帳號與既有帳號公司歸屬不直接修改；需要轉公司時另建帳號，避免歷史歸屬混淆。
- 臨時密碼僅當次顯示、24小時有效；正式密碼至少10字元，不能沿用臨時密碼。
- 每人可自行改密碼；基本資料由具權限的管理者維護。

### 6.8 停用、重新啟用、刪除、重設密碼

由資訊公司管理者在「帳號管理」操作。停用／刪除會使原密碼不可用，重新啟用後還要「重設臨時密碼」並交付本人，不能只按啟用。刪除是邏輯刪除，歷史保留，一般名單不再顯示。

有未結案件的負責工程師需先改派，才能停用／刪除；系統禁止移除最後一位可用資訊公司管理者。重設臨時密碼前確認本人身分，不能查看既有正式密碼。

### 6.9 忘記密碼與管理者緊急復原

有已驗證Email：登入頁「忘記密碼」輸入登入帳號，收取30分鐘有效的一次性重設連結。無Email、尚未驗證或收不到：資訊公司管理者在後台重設臨時密碼，交付本人，登入後強制更換。

如果唯一管理者遺失密碼，由有主機權限的維運者執行（不是一般使用者功能）：

```powershell
.\.venv\Scripts\python.exe backend/manage.py recover_admin --username zyadmin --confirm-recovery
```

Docker：

```bash
docker compose --env-file .env -f backend/deployment/compose.yaml run --rm web python manage.py recover_admin --username zyadmin --confirm-recovery
```

只會復原「啟用、未刪除」的資訊公司管理者，會輸出新臨時密碼並撤銷原密碼／登入狀態。停用或已刪除的管理者需另由維運者審查處理，不能假設recover_admin會自行啟用。

## 7. Gmail寄信、收件人與驗證

.env的EMAIL_HOST_USER及EMAIL_HOST_PASSWORD是**系統寄件用帳號**；每位使用者資料內的Email是**收件地址**，兩者不同。收件人可以是其他郵件服務，且不用提供自己的密碼。

Gmail需啟用兩步驟驗證並建立16碼應用程式密碼，填入時移除顯示用空格；不用一般Google登入密碼。若帳號政策沒有應用程式密碼選項，需使用允許的寄件帳號或另評估OAuth，現版未實作OAuth。[Google官方說明](https://support.google.com/mail/answer/185833)

```dotenv
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_HOST_USER=your-service-account@gmail.com
EMAIL_HOST_PASSWORD=REPLACE_WITH_GOOGLE_APP_PASSWORD
EMAIL_USE_TLS=1
DEFAULT_FROM_EMAIL=${EMAIL_HOST_USER}
```

儲存後重啟web及worker；使用者登入點「寄送驗證信」，打開最新信件的連結並在頁面確認驗證。**畫面顯示「已排入寄送」不是送達；資料表status=sent只代表SMTP接受，不保證在收件匣。** 可檢查垃圾郵件。

目前交接來源主機曾完成Gmail SMTP登入與一封驗證信接受；不代表新主機、新帳號或收件信箱已完成同樣驗證。

進度信不依賴使用者Email已驗證，但自助密碼重設必須已驗證；改Email後需重新驗證。已過期或重寄前的驗證信不要再使用，重新申請最新信件。Google帳號密碼變更可能撤銷應用程式密碼，需重新建立。

## 9. 更新版本與日常維護

1. 暫停對外寫入並停止worker，備份資料庫與附件，保留現行版本及設定的受控備份。
2. 交付新版程式，審查migrations；不要任意刪除既有遷移檔或用makemigrations生成未審查變更。
3. 更新套件／前端build／建置映像，執行check、migrate、collectstatic。
4. 啟動web與worker，確認登入、報修、Email、附件、PDF／Excel及操作紀錄。
5. 必須回復時，程式版本、SQL及附件需一致，不能只回復程式忽略資料結構變更。

Docker更新示例（先完成備份與維護安排）：

```bash
docker compose --env-file .env -f backend/deployment/compose.yaml stop web worker proxy
docker compose --env-file .env -f backend/deployment/compose.yaml build web worker proxy
docker compose --env-file .env -f backend/deployment/compose.yaml run --rm web python manage.py migrate --noinput
docker compose --env-file .env -f backend/deployment/compose.yaml run --rm web python manage.py collectstatic --noinput
docker compose --env-file .env -f backend/deployment/compose.yaml up -d web worker proxy
```

不要在更新或改密碼時使用`docker compose down -v`，它會刪除資料卷。Compose目前不是完整高可用或自動備份平台，排程、監控、憑證續期與資料保存政策需由接手維運者建立。

## 10. 備份與搬移既有資料

區分「新系統空庫安裝」與「搬移現有系統」；後者需要SQL、附件及對應程式版本，不能只交付程式碼，也不能在MySQL執行中直接複製mysql_data。

建議流程：

1. 安排維護，停止會寫入的web與worker。
2. 由DBA使用MySQL工具做一致性SQL匯出（InnoDB可採single-transaction），密碼使用安全提示或受限設定檔，不直接寫在命令列。
3. 同時備份private_media（Docker為attachments資料卷）、必要設定、憑證及程式版本資訊，機密另行安全交付。
4. 在新主機使用相容MySQL匯入SQL、還原附件，確認使用者及檔案目錄權限。
5. 建立新主機.env、自己的SMTP與資料庫帳密、正確SITE_URL；Session需要時重新登入，舊主機驗證連結重新申請。
6. 執行check、檢查migrations狀態、collectstatic，必要時依版本安排migrate。
7. 不重新bootstrap_admin；使用匯入的管理者帳號，必要時用已授權的recover_admin復原。
8. 在隔離環境核對表數、實際筆數、關聯、附件雜湊及抽樣下載，再切換正式DNS。

Docker持久化資料是mysql_data、attachments及static_files三個named volumes；其中資料庫與附件必須備份，static_files可由collectstatic重建。真正volume名稱包含Compose專案前綴，請依`docker volume ls`及容器掛載資訊辨認實際名稱，不直接假設名稱。

本精簡版不附一次性還原測試工具。正式備份由接手者使用MySQL標準工具及附件備份流程完成，備份需限制存取、加密並保存副本。
